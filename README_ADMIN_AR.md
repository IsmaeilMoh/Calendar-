# ICT بالعربي 3.3 — لوحة النشر وإشعارات المتابعين

## الملخص

- `admin.html`: لوحة نشر مستقلة في `https://ismaeilmoh.github.io/ictbelaraby/admin.html`، لا يظهر رابطها في التنقل العام. **هذا لا يجعل الصفحة سرية**: الحماية هي صلاحية GitHub فقط.
- `admin.js`: يستخدم GitHub Contents API مباشرة من متصفحك؛ لا تحفظ رموز الوصول في ملفات الموقع ولا في localStorage. يغادر الرمز الذاكرة عند إغلاق الصفحة.
- `analyses.json` و`recs.json` يحتفظان بنفس البنية الأساسية السابقة. يضاف `id` وتاريخ التحديث والتحكم بإشعار النشر؛ التعديلات على منشور قائم لا ترسل إشعارًا جديدًا.
- `analysis-images/`: صور الشارت. تُضغط الصور محليًا (JPEG) قبل رفعها. لا تفترض أن أي صورة هي ملك عام.
- `push-config.js`: ضع **App ID العام فقط** لتفعيل الاشتراك بعد إعداد OneSignal.
- `push/onesignal/OneSignalSDKWorker.js`: خدمة Push مستقلة بنطاق فرعي للحفاظ على عامل PWA الحالي.
- `.github/workflows/notify-new-posts.yml`: يرسل إشعارات تحليلات وتوصيات جديدة بعد كل Commit ناجح، بشرط إضافة الأسرار.
- `.github/workflows/notify-sessions-news.yml`: يتحقق تقريبًا كل 5 دقائق من بداية نوافذ ICT والأخبار عالية التأثير قبل 15 دقيقة.

## 1 — رفع الملفات بدون تعطيل بياناتك

استعمل حزمة التحديث الصغيرة، وارفع الملفات الجديدة واستبدل فقط `app.js`, `style.css`, `index.html`, `sw.js`. لا ترفع ملفات JSON الابتدائية التي قد تستبدل بياناتك المتزامنة. لا تغير Workflow التحديث الاقتصادي والأسعار والأخبار. أضف ملفي `notify-*.yml` للمجلد `.github/workflows/` كما فعلت سابقًا، وأضف `scripts/notify_push.py`.

## 2 — رمز دخول اللوحة من GitHub

1. افتح GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
2. اختر مالك المستودع، وحدد مستودع `ictbelaraby` فقط، وصلاحية **Repository permissions → Contents: Read and write**؛ ضع تاريخ انتهاء قصيرًا ويمكن إلغاؤه لاحقًا.
3. لا تنسخ الرمز لأي شخص ولا ترفعه إلى GitHub. افتح `admin.html` والصقه في حقل الدخول ثم اضغط اتصال.
4. يمكنك إنشاء تحليل أو توصية أو تحرير منشور سابق، ومعاينة المحتوى قبل النشر. صور الشارت تُرفع إلى `analysis-images`، ثم تُحفظ بيانات المنشور.
5. زر **حفظ مسودة محلية** يحفظ النصوص على نفس الجهاز فقط (ليس تشفيرًا خاصًا). لا تضع أسرارًا في المسودات.

**توضيح أمني:** Fine-grained PAT يتيح تعديل محتوى هذا المستودع طالما أنه صالح؛ استخدمه على جهاز موثوق ولا تشاركه. هذه آلية عملية لحساب المالك وليست نظام تسجيل دخول متعدد المستخدمين، أو لوحة خادم خاصة.

## 3 — تفعيل OneSignal Web Push (إعداد إلزامي لمتابعين والتطبيق مغلق)

1. أنشئ حسابًا في https://onesignal.com ، ثم Web Push app للموقع الأصلي: `https://ismaeilmoh.github.io` (الأصل نفسه). اختر **Custom Code**.
2. افتح `push-config.js` وضع **App ID العام** مكان النص الفارغ؛ لا تضع REST API Key في أي ملف منشور.
3. تأكد من فتح هذا الملف علنًا: `https://ismaeilmoh.github.io/ictbelaraby/push/onesignal/OneSignalSDKWorker.js`.
4. تم إعداد SDK لطلب المسار `/ictbelaraby/push/onesignal/OneSignalSDKWorker.js` والنطاق `/ictbelaraby/push/onesignal/` حتى لا يستبدل `sw.js` الأساسي.
5. في GitHub → Settings → Secrets and variables → Actions → New repository secret، أضف سرين: `ONESIGNAL_APP_ID` (معرّف التطبيق العام) و`ONESIGNAL_REST_API_KEY` (المفتاح السري من OneSignal).
6. افتح الموقع ثم مركز التنبيهات واضغط «الاشتراك في إشعارات الخلفية»؛ اسمح للمتصفح بالإشعارات. يمكن للمتابع اختيار فئات الإشعارات باستخدام مربعات الاختيار. **يجب اختبار وصول الإشعارات على جهاز حقيقي**.
7. على iPhone/iPad، قد يتطلب Web Push إضافة PWA إلى الشاشة الرئيسية (iOS 16.4+). لا يعمل في جميع المتصفحات والأوضاع الخاصة.

**لا تضع مفتاح OneSignal REST API في JavaScript أو في ملف JSON منشور أبدًا.**

## 4 — اختبار الإرسال

- في لوحة النشر، أنشئ منشورًا جديدًا وحدد «إرسال تنبيه»، ثم انشر. بعد نجاح Commit، افتح Actions → Notify followers of new trade ideas، وافحص سجل التنفيذ. يجب وجود مشترك فعلي وتصاريح OneSignal.
- للتنبيهات المجدولة، افتح Actions → Scheduled ICT and economic push alerts. يعمل تلقائيًا كل خمس دقائق تقريبًا، وقد يتأخر بسبب جدولة GitHub Actions؛ لا تضمن هذه الآلية وصول إشعار بالدقيقة ولا تصلح كخدمة تنبيه حرجة.
- لا ترسل مهمة المنشورات إشعارات لتعديلات المنشورات القديمة. أثناء التثبيت الأول لا يعاد إرسال إشعارات لجميع منشورات الأرشيف.
- تُقرأ أحداث الأجندة من `calendar-live.json` كما هي. **تتحقق المهمة من `date` و`impact`**؛ إذا تغيّرت بنية مصدر البيانات، يلزم ضبط السكربت.

## حدود تقنية صريحة

- عرض لوحة النشر في رابط عام لا يعني أنها محمية بكلمة مرور، لكن GitHub API يرفض الكتابة دون صلاحية صحيحة.
- نجاح GitHub Actions وحده لا يعني وصول Push؛ يجب التأكد من اشتراك OneSignal وسجل طلبات API وموافقة الجهاز.
- إذا اخترت لاحقًا صلاحيات متعددة للمحررين أو جدولة دقيقة، نحتاج خادمًا وحسابات فعلية بدل رمز GitHub الشخصي.
- التنبيهات عبر GitHub Scheduler قد تتأخر أو تتعطل وقت الضغط. الأخبار المتوسطة منخفضة الأهمية لا تُرسل في الخلفية افتراضيًا؛ تنبيهات الخلفية قبل الأخبار عالية التأثير فقط.
- في البداية تنبيهات الأخبار 15 دقيقة قبل الإصدار للجميع، بينما خيار 5/30/60 دقيقة الموجود في الموقع يخص **التنبيه المحلي أثناء فتح الموقع**.
- تنبيهات OneSignal تتطلب تمكينًا مستقلًا من المستخدم ولا تبدأ بمجرد رفع الملفات.
